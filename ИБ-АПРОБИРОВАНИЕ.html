Замена паролей — где и как

Подробный справочник всех параметров: раздел 📖 Параметры

① PostgreSQL — параметр DBPASS

  1. Панель [3] → 4 (SSH) или на узле БД:
sudo bash output/03-database/02-change-password.sh 'NovyjParol123!'
📄 Полный текст файлаoutput/03-database/02-change-password.sh
#!/bin/bash
# Termidesk 7.0 — смена пароля пользователя PostgreSQL
# Запуск: sudo bash 02-change-password.sh 'НовыйПароль'
# Или:   export TERMIDESK_DB_NEW_PASS='НовыйПароль'; sudo -E bash 02-change-password.sh
set -euo pipefail

DBUSER='termideskdb'
DBNAME='termidesk'
NEW_PASS="${1:-${TERMIDESK_DB_NEW_PASS:-}}"

if [ -z "$NEW_PASS" ]; then
  read -rsp "Новый пароль для $DBUSER: " NEW_PASS
  echo
fi

sudo su - postgres -c "psql -c \"ALTER USER $DBUSER WITH PASSWORD '$NEW_PASS';\""

echo "Пароль PostgreSQL для $DBUSER изменён."
echo "Обновите DBPASS в /etc/opt/termidesk-vdi/termidesk.conf на всех диспетчерах и CeleryMan."
echo "При OpenBao — обновите секрет в $SECRETS_OPENBAO_DB_PATH и перезапустите termidesk-vdi."
  1. На каждом диспетчере и CeleryMan: /etc/opt/termidesk-vdi/termidesk.conf → DBPASS
  2. Или sudo /opt/termidesk/sbin/termidesk-config → «Настройка подключения к СУБД»
  3. sudo systemctl restart termidesk-vdi
  4. Windows: config/termidesk-settings.json → database.password
  5. OpenBao: секрет SECRETS_OPENBAO_DB_PATH

② RabbitMQ — RABBITMQ_PASS и coordinatorPass

📄 Полный текст файлаoutput/04-rabbitmq/02-change-password.sh
#!/bin/bash
# Termidesk 7.0 — смена пароля пользователя RabbitMQ
# Запуск: sudo bash 02-change-password.sh 'НовыйПароль'
set -euo pipefail

RMQ_USER='admin'
VHOST='/'
NEW_PASS="${1:-${TERMIDESK_RMQ_NEW_PASS:-}}"

if [ -z "$NEW_PASS" ]; then
  read -rsp "Новый пароль для $RMQ_USER: " NEW_PASS
  echo
fi

sudo rabbitmqctl change_password "$RMQ_USER" "$NEW_PASS"
sudo rabbitmqctl set_permissions -p "$VHOST" "$RMQ_USER" ".*" ".*" ".*"

echo "Пароль RabbitMQ для $RMQ_USER изменён."
echo "Обновите RABBITMQ_PASS и coordinatorPass на диспетчерах, шлюзах и в termidesk.conf."
  1. Диспетчеры: RABBITMQ_PASS в termidesk.conf
  2. Шлюзы: coordinatorPass, при необходимости coordinatorUrl
  3. Панель [4] → 4 · JSON: rabbitmq.password, gateway.coordinatorPass

Блокировка сессии по неактивности

Должна настраиваться длительность неактивности; восстановление — только после повторной аутентификации.

  1. Портал → «Система» → «Системные настройки» → безопасность/сессии
  2. Политики пользовательского портала и клиентов Connect
  3. Проверка: после таймаута без действий — новый логин обязателен

Срок действия API-токена — два разных механизма

Важно: в гайде раньше смешивались разные токены. Ниже — что менять в вашем случае.

A. Токен REST API диспетчера (X-Auth-Token после /api/auth/v7.0/login)

Меняется в веб-портале администратора, не в termidesk.conf:

  1. → Настройки → Системные параметры → Безопасность
  2. Параметр «Длительность сессии администратора, с» — задайте срок в секундах (например 1800)
  3. Сохраните; выполните POST /api/auth/v7.0/login и проверьте, когда тот же X-Auth-Token начнёт отдавать 401
  4. Отозвать вручную: GET или POST /api/auth/v7.0/legacy/logout с заголовком X-Auth-Token

Подробнее: карточка X-Auth-Token

B. JWT Агрегатора (AGGREGATOR_ACCESS_TOKEN_TTL_SECONDS, по умолчанию 600)

Только если в архитектуре есть Агрегатор. Меняется на узле Агрегатора:

  1. SSH на узел с TERMIDESK_FARM_MODE=aggregator
  2. sudo /opt/termidesk/sbin/termidesk-config → «Настройки Агрегатора» → «Время жизни токена Агрегатора, секунд» → новое значение
  3. Или вручную: /etc/opt/termidesk-vdi/termidesk.conf → AGGREGATOR_ACCESS_TOKEN_TTL_SECONDS='300'
  4. Обязательно перезапуск: termidesk-config → «Перезапуск служб»

📄 Полный текст файлаoutput/10-ssl/generate-user-certificate.sh
#!/bin/bash
# Генерация CA и пользовательского сертификата для mTLS Termidesk
# Результат: /etc/opt/termidesk-vdi/mtls/{ca.crt,client.crt,client.key}
set -euo pipefail

CN="${1:-termidesk-user}"
DAYS="${2:-365}"
OUT="/etc/opt/termidesk-vdi/mtls"
sudo mkdir -p "$OUT"
cd "$OUT"

if [ ! -f ca.key ]; then
  sudo openssl genrsa -out ca.key 4096
  sudo openssl req -x509 -new -nodes -key ca.key -sha256 -days $DAYS \
    -subj "/CN=Termidesk-Internal-CA" -out ca.crt
fi

sudo openssl genrsa -out client.key 2048
sudo openssl req -new -key client.key -subj "/CN=$CN" -out client.csr
sudo openssl x509 -req -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out client.crt -days $DAYS -sha256
sudo rm -f client.csr ca.srl
sudo chmod 640 client.key
sudo chown root:termidesk client.key client.crt ca.crt 2>/dev/null || true

echo "CA: $OUT/ca.crt"
echo "Клиент: $OUT/client.crt + $OUT/client.key"
echo "Импортируйте ca.crt в доверенные на клиенте; client.p12 — через openssl pkcs12 при необходимости."

#!/bin/bash
# ИБ-91 — предупреждение при заполнении журналов
set -euo pipefail
LOG_DIR='/var/log/termidesk'
THRESHOLD="${1:-80}"
for dir in "$LOG_DIR" /var/log/termidesk; do
  [ -d "$dir" ] || continue
  pct=$(df -P "$dir" | awk 'NR==2 {print int($5)}')
  if [ "$pct" -ge "$THRESHOLD" ]; then
    echo "WARNING ИБ-91: $dir заполнен на ${pct}%"
    exit 1
  fi
  echo "OK ИБ-91: $dir — ${pct}%"
done

# Генерация CA и пользовательского сертификата для mTLS Termidesk
# Результат: /etc/opt/termidesk-vdi/mtls/{ca.crt,client.crt,client.key}
set -euo pipefail

CN="${1:-termidesk-user}"
DAYS="${2:-365}"
OUT="/etc/opt/termidesk-vdi/mtls"
sudo mkdir -p "$OUT"
cd "$OUT"

if [ ! -f ca.key ]; then
  sudo openssl genrsa -out ca.key 4096
  sudo openssl req -x509 -new -nodes -key ca.key -sha256 -days $DAYS \
    -subj "/CN=Termidesk-Internal-CA" -out ca.crt
fi

sudo openssl req -new -key client.key -subj "/CN=$CN" -out client.csr
sudo openssl x509 -req -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out client.crt -days $DAYS -sha256
sudo rm -f client.csr ca.srl
sudo chmod 640 client.key
sudo chown root:termidesk client.key client.crt ca.crt 2>/dev/null || true

echo "CA: $OUT/ca.crt"
echo "Клиент: $OUT/client.crt + $OUT/client.key"
