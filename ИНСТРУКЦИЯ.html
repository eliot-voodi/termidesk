16. Поддержка изменений панели

Termidesk VDI 7.0 — Панель администрирования

Полная инструкция по использованию

1. Назначение

  1. Собрать параметры развёртывания Termidesk VDI 7.0 в интерактивном режиме.
  2. Сохранить их в config/termidesk-settings.json.
  3. Сгенерировать bash/PowerShell-скрипты и конфиги в каталог output/.
  4. (Опционально) выполнить шаги на Linux-узлах по SSH из Windows.
  5. Настроить домены, поставщиков, фонды VDI, мониторинг, backup и журналирование.

    6. 2. Требования

powershell -ExecutionPolicy Bypass -File .\Start-TermideskMenu.ps1

      4. 2.4. Целевые узлы (Linux)

      • Astra Linux SE / CE (или ОС из матрицы совместимости Termidesk 7.0).
      • Доступ sudo для пользователя SSH.
      • Синхронизация времени (NTP) между всеми узлами.
      • DNS-записи (A/AAAA или /etc/hosts) для всех FQDN.
      • Открытые порты между компонентами (см. раздел 10).
      • Доступ к репозиторию пакетов Termidesk 7.0.

            • Вопрос мастера «Путь к dhparam.pem» — что он хочет

            /etc/nginx/dhparam.pem

            Как сделать dhparam.pem (на балансировщике Linux)

            ssh USER@IP_БАЛАНСИРОВЩИКА
sudo mkdir -p /etc/nginx
sudo apt install -y openssl    # если ещё не установлен
sudo openssl dhparam -out /etc/nginx/dhparam.pem 4096
ls -lh /etc/nginx/dhparam.pem  # проверка; генерация 4096 может занять много минут
          • Количество ≥ 2.
          • Для каждого: NODE_NAME, FQDN, IP.
          • Первый узел помечается эталонным (isReference) — с него копируется /etc/opt/termidesk-vdi на остальные.
          • NODE_ROLES: для standard обычно ADMIN,USER; для minimal — ADMIN,USER,CELERYMAN.
          • URL портала администратора, логин/пароль admin.
          • ≥ 2 отдельных узла.
          • Порты health-check beat/worker (типично 8103 / 8104).
          • coordinatorUrl — например amqp://user@rabbit-host:5672/
          • coordinatorUser / coordinatorPass
          • healthCheckPath — например /api/health
          • daas-upstream-ws → шлюзы IP:websockify
          • daas-upstream-nodes → диспетчеры IP:dispatcherPort
          • HEALTH_CHECK_ACCESS_KEY — ключ доступа к health API Termidesk
          • METRICS_ACCESS_KEY — необязательно

              6.1. portal

            • url — HTTPS URL портала администрирования

            • user, port, keyPath — параметры удалённого выполнения

              • 6.3. environment

            • domain, ntpServer, termideskRepo, astraRepo

              • 6.4. cluster

            • deploymentType — standard | minimal
            • secretsStorage — config | openbao
            • referenceNode, dispatchers[], celeryManagers[], gateways[]
            • loadBalancers.fqdn, vip, nodes[]
            • nginx.* — listen, порты, каталоги snippets
            • tls.* — mode, пути сертификатов, cipher/stapling, DNS resolvers

                8. Рекомендуемый production-сценарий (чек-лист)

              3. Спроектировать схему узлов, VIP, DNS, сертификаты, сети.
              4. Подготовить ОС, NTP, firewall, репозитории (можно начать с [2]).
              5. Поднять HA PostgreSQL и проверить failover.
              6. Поднять RabbitMQ (кластер при необходимости).
              7. Запустить панель → [18] → [1] — ввести все параметры.
              8. Проверить JSON → [18] → [2].
              9. Выполнить шаги [18] → 1…8 по порядку (SSH + ручные гайды).
              10. Проверить [18] → 9 и веб-вход на VIP.
              11. Настроить домены [12], поставщиков и фонды [13].
              12. Включить мониторинг [15], backup [16], логи [17].
              13. Зафиксировать пароли в секретнице; ограничить ACL на termidesk-settings.json.

                14. 9. SSH: как панель выполняет шаги

              14. Скрипт сохраняется во временный файл на Windows.
              15. scp копирует его в /tmp/ на целевой узел.
              16. ssh … sudo bash /tmp/<script> запускает выполнение.
              17. Код возврата отображается в консоли.
                • Пользователь в sudoers (желательно NOPASSWD для автоматизации или интерактивный ввод пароля sudo).
                • Доступность TCP SSH-порта.
                • Для ключа — корректный keyPath в настройках.

                  • 10. Порты (ориентир)

                • LB → диспетчеры (dispatcherPort)
                • LB → шлюзы (websockify port)
                • Диспетчеры/Celery → PostgreSQL, RabbitMQ
                • Шлюзы → RabbitMQ
                • Клиенты → VIP :443 (и :80 при редиректе)

                  • 11. Типичные ошибки и решения

                  ParserError / кракозябры в меню

                  Join-Path … Path is null в пункте [18]

                  ssh / scp не найдены

                  Permission denied / sudo password

                  nginx: duplicate ssl / ошибка nginx -t

                  Диспетчер не видит БД

                  Шлюз не регистрируется

                  Самоподписанный сертификат — браузер ругается

                  Мастер [18] спрашивает «Путь к dhparam.pem»

                  ExecutionPolicy

                  Случайно загрузили example поверх боевого JSON ([C]→2)

                  12. Безопасность

                  1. Не храните боевые пароли в example-файлах и публичных репозиториях.
                  2. Ограничьте NTFS ACL на config\termidesk-settings.json.
                  3. Предпочитайте SSH-ключи паролям.
                  4. В production — корпоративные TLS-сертификаты, не self-signed.
                  5. Рассмотрите OpenBao для секретов БД/брокера.
                  6. Ротируйте HEALTH_CHECK_ACCESS_KEY и пароли БД/RabbitMQ по политике ИБ.
                  7. Логи скриптов могут содержать чувствительные данные — чистите /tmp на узлах.

                      16. Поддержка изменений панели

                      1. Остановите меню.
