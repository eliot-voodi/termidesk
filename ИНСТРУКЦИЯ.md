# Termidesk VDI 7.0 — Панель администрирования

## Полная инструкция по использованию

Документ описывает PowerShell-панель `Start-TermideskMenu.ps1`: назначение, требования, структуру проекта, каждый пункт меню, пошаговую настройку отказоустойчивого (HA) кластера, параметры конфигурации, порты, SSH, типичные ошибки и ссылки на официальную документацию Termidesk 7.0.

Официальная документация: https://termidesk.ru/docs/ru-termidesk-doc/v7.0/index.html

---

## 1. Назначение

Панель помогает администратору:

1. Собрать параметры развёртывания Termidesk VDI 7.0 в интерактивном режиме.
2. Сохранить их в `config/termidesk-settings.json`.
3. Сгенерировать bash/PowerShell-скрипты и конфиги в каталог `output/`.
4. (Опционально) выполнить шаги на Linux-узлах по SSH из Windows.
5. Настроить домены, поставщиков, фонды VDI, мониторинг, backup и журналирование.

Панель **не заменяет** официальный `termidesk-config` на Linux и не поднимает Patroni/HA PostgreSQL «из коробки». Она готовит конфигурацию и сценарии под вашу инфраструктуру и помогает пройти установку по документации Termidesk.

## 2. Требования

### 2.1. Рабочая станция администратора (Windows)

| Компонент | Требование |
|-----------|------------|
| ОС | Windows 10/11 или Windows Server 2016+ |
| PowerShell | 5.1 или новее (`$PSVersionTable.PSVersion`) |
| Права | Возможность запускать `.ps1` (ExecutionPolicy) |
| SSH-клиент | `ssh` и `scp` в PATH (OpenSSH Client в Windows) |
| Сеть | Доступ по SSH к целевым Linux-узлам Astra Linux / поддерживаемой ОС |

Проверка OpenSSH:

```powershell
Get-Command ssh, scp
ssh -V
```

Если команд нет: «Параметры → Приложения → Дополнительные компоненты → OpenSSH Client».

### 2.2. Политика выполнения скриптов

Если появляется ошибка ExecutionPolicy:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Или одноразовый запуск:

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-TermideskMenu.ps1
```

### 2.3. Кодировка файлов (критично)

Скрипты содержат кириллицу. **PowerShell 5.1** корректно читает `.ps1` / `.psm1` только в **UTF-8 with BOM**.

Симптомы повреждения кодировки:

- В меню вместо «Показать» видно `ÐŸÐ¾ÐºÐ°Ð·Ð°Ñ‚ÑŒ`
- ParserError: `Unexpected token`, `The string is missing the terminator`

Что делать:

1. Берите свежую копию проекта из исходного каталога (после исправления BOM).
2. Не открывайте и не сохраняйте `.ps1` в редакторах, которые снимают BOM (или пересохраняйте как UTF-8 with BOM).
3. Не распаковывайте архив через утилиты, меняющие кодировку текста.

### 2.4. Целевые узлы (Linux)

- Astra Linux SE / CE (или ОС из матрицы совместимости Termidesk 7.0).
- Доступ `sudo` для пользователя SSH.
- Синхронизация времени (NTP) между всеми узлами.
- DNS-записи (A/AAAA или `/etc/hosts`) для всех FQDN.
- Открытые порты между компонентами (см. раздел 10).
- Доступ к репозиторию пакетов Termidesk 7.0.

### 2.5. Рекомендуемый состав HA (standard)

Минимально для отказоустойчивости:

| Роль | Кол-во | Назначение |
|------|--------|------------|
| PostgreSQL (кластер) | 2–3 | Общая БД Termidesk |
| RabbitMQ | 1+ (лучше кластер) | Очереди задач |
| Универсальный диспетчер | ≥ 2 | Портал, API, сессии |
| CeleryMan | ≥ 2 | Менеджер рабочих мест |
| Termidesk Connect (шлюз) | ≥ 2 | Доступ пользователей к ВРМ |
| nginx (балансировщик) | ≥ 1 (лучше 2 + VIP) | Единая точка входа |

Тип **minimal**: CeleryMan совмещён с диспетчерами (`NODE_ROLES` включает `CELERYMAN`). Подходит для лабораторий, не для production.

## 4. Первый запуск

1. Скопируйте каталог `termidesk` целиком (без потери BOM).
2. Откройте PowerShell в каталоге проекта:

```powershell
cd C:\path\to\termidesk
.\Start-TermideskMenu.ps1
```

3. При первом запуске, если нет `config/termidesk-settings.json`, он создаётся из `termidesk-settings.example.json`.
4. Откроется главное меню.

| Ссылки на docs.termidesk.ru | **[D]** |
| Эта инструкция | **[H]** |

**Этап: TLS/SSL балансировщика**

| Режим | Поведение |
|-------|-----------|
| Самоподписанный | Скрипт сгенерирует cert/key и `dhparam.pem` на LB |
| Существующие файлы | Скрипт пропишет пути к вашим cert/key (файлы должны быть на Linux-узле LB) |

#### Вопрос мастера «Путь к dhparam.pem» — что он хочет

Это **не** повторный запрос сертификата.

`dhparam.pem` — служебный файл параметров Diffie–Hellman для nginx (директива `ssl_dhparam`). Нужен для усиления TLS. Это отдельный файл, не `.crt` и не `.key`.

**Что вводить в мастере:**

```text
/etc/nginx/dhparam.pem
```

#### Как сделать dhparam.pem (на балансировщике Linux)

```bash
ssh USER@IP_БАЛАНСИРОВЩИКА
sudo mkdir -p /etc/nginx
sudo apt install -y openssl    # если ещё не установлен
sudo openssl dhparam -out /etc/nginx/dhparam.pem 4096
ls -lh /etc/nginx/dhparam.pem  # проверка; генерация 4096 может занять много минут
```

Либо не создавайте заранее: на шаге **[18] → 8** (nginx) скрипт создаст файл сам, если его нет по указанному пути (тоже долго).

Для стенда можно `2048` вместо `4096`. Production — `4096`.

Подробный разбор: `НАСТРОЙКА-КЛАСТЕРА.html` → «Как сделать файл dhparam.pem».

Все три пути (cert, key, dhparam) — **только Linux-пути на балансировщике**.  
Нельзя: `C:\_Scripts\SSL\...`. Нужно сначала скопировать `.crt`/`.key` на LB в `/etc/ssl/...`.

Также указываются DNS resolver primary (и secondary) для `ssl_stapling` — **ваши** DNS.

Для self-signed дополнительно: срок (дней), размер ключа RSA, CN (обычно FQDN VIP портала).

**Этап: Универсальные диспетчеры**

- Количество ≥ 2.
- Для каждого: `NODE_NAME`, `FQDN`, `IP`.
- Первый узел помечается **эталонным** (`isReference`) — с него копируется `/etc/opt/termidesk-vdi` на остальные.
- `NODE_ROLES`: для standard обычно `ADMIN,USER`; для minimal — `ADMIN,USER,CELERYMAN`.
- URL портала администратора, логин/пароль admin.

На эталоне после установки запускается интерактивный `/opt/termidesk/sbin/termidesk-config` — панель генерирует **гайд**, а не полностью безмолвную установку GUI-мастера.

---

**Этап: CeleryMan** (только standard)

- ≥ 2 отдельных узла.
- Порты health-check beat/worker (типично `8103` / `8104`).

Конфиг локали Celery берётся из шаблона `termidesk-vdi.local.template`.

---

**Этап: Termidesk Connect (шлюзы)**

Для каждого шлюза: имя, FQDN, IP, порт websockify (часто `5099`).

Общие:

- `coordinatorUrl` — например `amqp://user@rabbit-host:5672/`
- `coordinatorUser` / `coordinatorPass`
- `healthCheckPath` — например `/api/health`

---

**Этап: Балансировщики nginx**

| Параметр | Описание |
|----------|----------|
| FQDN VIP | Имя, по которому ходят пользователи |
| VIP IP | Необяз., если Keepalived/другое |
| Узлы LB | name / fqdn / ip |
| listen HTTP/HTTPS | Например `0.0.0.0:80` и `0.0.0.0:443 ssl` |
| Порт HTTPS диспетчеров | Обычно `443` |
| proxy timeout | Секунды (в доках часто большие значения для websockify) |
| Каталоги snippets / include-пути | Пути на Linux-узле nginx |

Upstream’ы в конфиге:

- `daas-upstream-ws` → шлюзы `IP:websockify`
- `daas-upstream-nodes` → диспетчеры `IP:dispatcherPort`

---

**Этап: Health Check**

- `HEALTH_CHECK_ACCESS_KEY` — ключ доступа к health API Termidesk
- `METRICS_ACCESS_KEY` — необязательно

---

**Сводка и сохранение**

После подтверждения:

1. Пишется `config/termidesk-settings.json`
2. Синхронизируется `config/cluster-config.json`
3. Генерируются файлы в `output/18-ha-wizard/`
4. Обнуляется прогресс развёртывания (фаза `configured`)

#### Порядок развёртывания после сбора параметров

Выполняйте шаги **строго по порядку**:

| Шаг | Скрипт | Куда | Примечание |
|-----|--------|------|------------|
| 1 | `01-prepare-environment.sh` | Инфраструктурные/все узлы | NTP, apt repo |
| 2 | `02-postgresql-setup.sh` | Узел(ы) PostgreSQL | Создание БД/роли |
| 3 | `03-rabbitmq-setup.sh` | Узел RabbitMQ | Брокер + management |
| 4 | `04-dispatcher-reference.sh` | Эталонный диспетчер | Гайд + termidesk-config |
| 5 | `05-dispatcher-additional.sh` | Остальные диспетчеры | Копия конфига с эталона |
| 6 | `06-celery-setup.sh` | CeleryMan (standard) | Установка менеджеров |
| 7 | `07-gateway-setup.sh` | Шлюзы | Гайд Connect |
| 8 | `08-nginx-lb-setup.sh` | Балансировщик(и) | nginx + TLS + site |
| 9 | `09-healthcheck.ps1` | С Windows | Пинг узлов / сводка |

Для **minimal** шаг Celery пропускается (роли на диспетчерах).

Шаги-гайды (диспетчеры, шлюзы) выводят инструкции на экран — часть действий делается вручную в `termidesk-config` / UI Connect.

После успешного SSH-шага ключ шага пишется в `ha-wizard-state.json` (метка `[✓]`). **[R]** сбрасывает только прогресс, не конфигурацию.

## 8. Рекомендуемый production-сценарий (чек-лист)

> **Подробный пошаговый сценарий «что и как делать»:** файлы  
> `НАСТРОЙКА-КЛАСТЕРА.html` / `НАСТРОЙКА-КЛАСТЕРА.md`  
> (меню **[H] → [1]** или внутри **[18] → [G]**).

Краткий чек-лист:

1. Спроектировать схему узлов, VIP, DNS, сертификаты, сети.
2. Подготовить ОС, NTP, firewall, репозитории (можно начать с [2]).
3. Поднять HA PostgreSQL и проверить failover.
4. Поднять RabbitMQ (кластер при необходимости).
5. Запустить панель → **[18] → [1]** — ввести все параметры.
6. Проверить JSON → **[18] → [2]**.
7. Выполнить шаги **[18] → 1…8** по порядку (SSH + ручные гайды).
8. Проверить **[18] → 9** и веб-вход на VIP.
9. Настроить домены **[12]**, поставщиков и фонды **[13]**.
10. Включить мониторинг **[15]**, backup **[16]**, логи **[17]**.
11. Зафиксировать пароли в секретнице; ограничить ACL на `termidesk-settings.json`.

## 9. SSH: как панель выполняет шаги

1. Скрипт сохраняется во временный файл на Windows.
2. `scp` копирует его в `/tmp/` на целевой узел.
3. `ssh … sudo bash /tmp/<script>` запускает выполнение.
4. Код возврата отображается в консоли.

Требования:

- Пользователь в `sudoers` (желательно NOPASSWD для автоматизации или интерактивный ввод пароля sudo).
- Доступность TCP SSH-порта.
- Для ключа — корректный `keyPath` в настройках.

Если SSH не нужен — используйте **[O]**, копируйте `.sh` вручную и запускайте на узлах.

## 10. Порты (ориентир)

| Порт | Сервис |
|------|--------|
| 22 | SSH (администрирование) |
| 80 / 443 | nginx VIP (HTTP/HTTPS) |
| 443 | Универсальный диспетчер (HTTPS) |
| 5432 | PostgreSQL |
| 5672 | RabbitMQ AMQP |
| 15672 | RabbitMQ Management |
| 5099 | Termidesk Connect websockify (часто) |
| 8103 | Celery beat healthcheck |
| 8104 | Celery worker healthcheck |
| 8200 | OpenBao |

Точные порты задаёте **вы** в мастере [18] — таблица лишь типичный ориентир из документации/практики.

Между балансировщиком и бэкендами должны быть разрешены:

- LB → диспетчеры (`dispatcherPort`)
- LB → шлюзы (websockify port)
- Диспетчеры/Celery → PostgreSQL, RabbitMQ
- Шлюзы → RabbitMQ
- Клиенты → VIP :443 (и :80 при редиректе)

## 11. Типичные ошибки и решения

### ParserError / кракозябры в меню

Кодировка без BOM. Замените проект свежей копией UTF-8 BOM. См. §2.3.

### `Join-Path … Path is null` в пункте [18]

Устаревшая версия модуля HaWizard. Обновите `modules/Termidesk.HaWizard.psm1` (использует `Get-TermideskConfigPath`).

### `ssh` / `scp` не найдены

Установите OpenSSH Client в Windows.

### Permission denied / sudo password

Настройте sudo NOPASSWD или выполняйте скрипты вручную под root.

### nginx: duplicate `ssl` / ошибка `nginx -t`

В `listenHttps` указывайте полную директиву, например `0.0.0.0:443 ssl` (без лишнего второго `ssl` вне шаблона). Перегенерируйте скрипты после правки настроек.

### Диспетчер не видит БД

Проверьте `pg_hba.conf` (CIDR), firewall 5432, что указан master в cluster mode, пароль/SSL.

### Шлюз не регистрируется

Проверьте `coordinatorUrl`, учётки RabbitMQ, сеть до брокера, логи Connect.

### Самоподписанный сертификат — браузер ругается

Ожидаемо. Для production используйте режим «существующие файлы» и корпоративный/публичный сертификат на VIP FQDN; распространите корневой CA на клиенты.

### Мастер [18] спрашивает «Путь к dhparam.pem»

Ответ: `/etc/nginx/dhparam.pem`. Это не сертификат, а файл Diffie–Hellman для nginx. Подробно — в `НАСТРОЙКА-КЛАСТЕРА.html` и в этапе TLS этой инструкции. Не указывайте пути `C:\...`.

### ExecutionPolicy

См. §2.2.

### Случайно загрузили example поверх боевого JSON ([C]→2)

Восстановите из backup. Храните копию `termidesk-settings.json` вне каталога проекта.

## 12. Безопасность

1. Не храните боевые пароли в example-файлах и публичных репозиториях.
2. Ограничьте NTFS ACL на `config\termidesk-settings.json`.
3. Предпочитайте SSH-ключи паролям.
4. В production — корпоративные TLS-сертификаты, не self-signed.
5. Рассмотрите OpenBao для секретов БД/брокера.
6. Ротируйте `HEALTH_CHECK_ACCESS_KEY` и пароли БД/RabbitMQ по политике ИБ.
7. Логи скриптов могут содержать чувствительные данные — чистите `/tmp` на узлах.
