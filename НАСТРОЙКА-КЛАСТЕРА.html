Полная настройка отказоустойчивого кластера Termidesk VDI 7.0

A. Что вы получите в итоге

  1. Общая БД PostgreSQL (режим DB_CLUSTER_MODE=cluster в Termidesk).
  2. Брокер RabbitMQ (очереди задач и регистрация шлюзов).
  3. ≥ 2 Универсальных диспетчера (портал/API), один — эталон.
  4. ≥ 2 Менеджера рабочих мест CeleryMan (в типе standard — отдельные узлы).
  5. ≥ 2 шлюза Termidesk Connect (websockify).
  6. Балансировщик nginx с VIP FQDN для пользователей.
  7. Единый termidesk-settings.json и скрипты в output/18-ha-wizard/.

    8. B. Перед началом: проектирование (обязательно)

    • DNS-домен (например corp.example.ru)
    • NTP-сервер
    • URL репозитория Termidesk 7.0
    • Пароли: БД, RabbitMQ, admin портала, SSH
    • Сертификат VIP (корпоративный) или решение использовать self-signed на стенде
    • CIDR сети приложений для pg_hba.conf (например 10.10.0.0/24)
    • DNS-резолверы для nginx ssl_stapling (внутренние DNS)

      • Выбор типа развёртывания

      C. Подготовка Windows-станции администратора

      1. Скопируйте каталог termidesk целиком (файлы .ps1/.psm1 должны быть UTF-8 с BOM).
      2. Установите OpenSSH Client (ssh, scp в PATH).
      3. Разрешите скрипты при необходимости:
        4. Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
      4. Проверьте доступ к каждому Linux-узлу:
        5. ssh -p 22 USER@IP "hostname; sudo -n true || sudo -v; timedatectl || date"
      5. Запустите панель:
        6. cd C:\path\to\termidesk
.\Start-TermideskMenu.ps1
      6. Откройте справку: меню [H] → HTML-инструкция; этот документ — НАСТРОЙКА-КЛАСТЕРА.html.

        7. D. Подготовка Linux-узлов (до панели или шаг 1)

      7. Установить поддерживаемую ОС (Astra Linux и т.п. по матрице Termidesk 7.0).
      8. Задать hostname = короткое имя; прописать FQDN в DNS или /etc/hosts на всех узлах.
      9. Создать пользователя SSH с sudo.
      10. Открыть firewall между ролями (см. раздел портов ниже).
      11. Обеспечить доступ к репозиторию Termidesk и обновлениям ОС.

          • 7) TLS балансировщика

          Что спрашивает мастер и что отвечать

          Вопрос «Путь к dhparam.pem» — что он от вас хочет

          /etc/nginx/dhparam.pem

          Как сделать файл dhparam.pem

          1. Подключитесь по SSH к балансировщику:
            2. ssh USER@IP_БАЛАНСИРОВЩИКА
          2. Создайте каталог (если нужно) и сгенерируйте файл:
            3. sudo mkdir -p /etc/nginx
sudo openssl dhparam -out /etc/nginx/dhparam.pem 4096
          3. Дождитесь окончания. Генерация 4096 бит может занять от нескольких минут до 15–20+ минут — это нормально, не прерывайте.
          4. Проверьте, что файл появился и не пустой:
            5. ls -lh /etc/nginx/dhparam.pem
sudo head -n 2 /etc/nginx/dhparam.pem
          5. Права (по желанию, только root читает ключ-подобные файлы):
            6. sudo chmod 644 /etc/nginx/dhparam.pem
          6. В мастере [18] на вопрос «Путь к dhparam.pem» укажите /etc/nginx/dhparam.pem.
          7. На шаге развёртывания nginx ([18] → 8) скрипт 08-nginx-lb-setup.sh сам выполнит openssl dhparam, если файла ещё нет.
          8. Учтите: шаг nginx «зависнет» на генерации на то же долгое время — это ожидаемо.
            9. sudo openssl dhparam -out /etc/nginx/dhparam.pem 2048
            sudo apt update
sudo apt install -y openssl

            Частая ошибка: пути Windows

            C:\_Scripts\SSL\certs\something.crt

              • F. Пошаговое развёртывание (выполнение)

              Шаг 1. Подготовка среды (01-prepare-environment.sh)

            • прописывает NTP;
            • добавляет репозиторий Termidesk (и Astra, если задан);
            • apt update.
              1. В [18] выбрать шаг 1, подтвердить SSH на целевой IP (или выполнить вручную на каждом узле).
              2. Повторить для всех узлов кластера (скрипт один — цель меняется).
              3. Проверить:
                4. timedatectl status   # или date на всех узлах — время совпадает
apt-cache policy termidesk-vdi

                Шаг 2. PostgreSQL (02-postgresql-setup.sh)

                • ставит postgresql (если ещё нет);
                • создаёт БД и пользователя;
                • печатает строку для pg_hba.conf.
                  1. Выполнить шаг 2 на DBHOST.
                  2. Вручную добавить в pg_hba.conf доступ из CIDR приложений (как в мастере), затем reload.
                  3. Если HA БД — настроить репликацию/Patroni по вашей схеме; убедиться, что приложение видит master.
                  4. Проверка с диспетчерской сети:
                    5. psql -h DBHOST -p 5432 -U DBUSER -d DBNAME -c 'SELECT 1'

                    Шаг 3. RabbitMQ (03-rabbitmq-setup.sh)

                    • ставит rabbitmq-server;
                    • кладёт конфиги из шаблонов;
                    • включает management plugin;
                    • перезапускает сервис.
                      1. Выполнить шаг 3.
                      2. Создать пользователя/vhost/права, если скрипт не создал их под ваши пароли (сверьте с официальным гайдом и вашими значениями из JSON):
                        3. sudo rabbitmqctl status
sudo rabbitmqctl list_users
# при необходимости:
# sudo rabbitmqctl add_user ...
# sudo rabbitmqctl set_permissions -p / ...
                      3. Открыть management UI http://RABBIT:15672 (если политика ИБ позволяет) и проверить доступ.
                      4. С узлов диспетчера/шлюза проверить TCP 5672.

                        5. Шаг 4. Первый диспетчер — эталон (04-dispatcher-reference.sh)

                      5. Открыть шаг 4 в меню — прочитать инструкцию / выполнить установку пакета.
                      6. На эталоне:
                        7. sudo apt install -y termidesk-vdi
cd /opt/termidesk/sbin
sudo ./termidesk-config
                      7. В termidesk-config указать те же параметры, что в termidesk-settings.json:
                        • farm mode / роли / NODE_NAME эталона;
                        • DB_CLUSTER_MODE, DBHOST…, DBNAME, DBUSER, DBPASS;
                        • RabbitMQ URL / user / password / vhost;
                        • secrets storage (config или OpenBao);
                        • HEALTH_CHECK_ACCESS_KEY.
                          1. Дождаться успешного старта служб:
                            2. systemctl status termidesk-vdi
# и связанные unit'ы по документации вашей сборки
                          2. Войти в веб-портал по https://эталон-FQDN (или временно по IP) под admin — убедиться, что UI открывается.
                          3. Сохранить каталог конфигурации для копирования на другие диспетчеры:
                            4. # с эталона (пример из гайда панели)
sudo tar czf /tmp/termidesk-vdi-etc.tgz -C /etc/opt termidesk-vdi
# или scp -r /etc/opt/termidesk-vdi user@other:/home/user/

                            Шаг 5. Дополнительные диспетчеры (05-dispatcher-additional.sh)

                          4. Скопировать /etc/opt/termidesk-vdi с эталона на целевой узел (в home, затем в /etc/opt/).
                          5. Установить пакет termidesk-vdi.
                          6. В конфиге сменить NODE_NAME на уникальное имя этого узла (роли как у диспетчеров).
                          7. Параметры БД и RabbitMQ — идентичны эталону (не создавать новую БД).
                          8. Запустить службы, проверить:
                            9. systemctl status termidesk-vdi
journalctl -u termidesk-vdi -e --no-pager | tail -n 50
                          9. Повторить для всех дополнительных диспетчеров.

                            10. Шаг 6. CeleryMan (06-celery-setup.sh) — только standard

                          10. Скопировать конфиг с эталонного диспетчера (/etc/opt/termidesk-vdi).
                          11. Выполнить скрипт шага 6 (или вручную): положить termidesk-vdi.local, выставить NODE_ROLES=CELERYMAN, установить пакет.
                          12. Уникальный NODE_NAME на каждом CeleryMan.
                          13. Проверить порты health (8103/8104 или ваши) и службы celery beat/worker по документации.
                          14. Повторить на втором (и далее) узле CeleryMan.

                            15. Шаг 7. Termidesk Connect — шлюзы (07-gateway-setup.sh)

                          15. Установить Termidesk Connect по официальной инструкции вашей версии.
                          16. Задать:
                            • coordinatorUrl, coordinatorUser, coordinatorPass — как в мастере;
                            • порт websockify;
                            • healthCheckPath.
                              1. Убедиться, что шлюз зарегистрирован в RabbitMQ и отвечает на health.
                              2. С балансировщика проверить доступность IP:websockify_port.

                                3. Шаг 8. Балансировщик nginx (08-nginx-lb-setup.sh)

                                • ставит nginx/openssl;
                                • генерирует self-signed или использует ваши пути сертификатов;
                                • пишет snippets SSL и site с upstream на диспетчеры и шлюзы;
                                • nginx -t и restart.
                                  1. Если режим «существующие файлы» — заранее положите cert/key (и при необходимости dhparam) по указанным путям.
                                  2. Выполнить шаг 8.
                                  3. Проверить:
                                    4. sudo nginx -t
systemctl status nginx
curl -kI https://VIP-FQDN/
# websockify путь зависит от конфигурации клиентов
                                  4. DNS: A-запись VIP FQDN → VIP IP (или hosts на клиентах для стенда).
                                  5. Если два LB — настройте Keepalived/внешний VIP отдельно; скрипт настраивает nginx на конкретном узле.
